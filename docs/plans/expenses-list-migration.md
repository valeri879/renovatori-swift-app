# ხარჯების (`/admin/expenses-list`) მიგრაციის გეგმა

> **სტატუსი:** ეტაპი 1 შესრულებულია (2026-10-27) არჩეული პასუხებით: მხოლოდ სია, წაშლა ადმინისთვის დადასტურებით, Telegram შეტყობინება წაშლისას რჩება.
> ეტაპი 2 + ეტაპი 3-ის ნაწილი შესრულებულია (2026-10-27): დეტალური ეკრანი (ფინანსები, ინფორმაცია, პროგრესი, ხარჯები ტიპებით ფილტრით, ჩარიცხვები, ხარჯები სურათებით) და **ხარჯის / ჩარიცხვის დამატება** (Telegram და კლიენტის ელ-ფოსტა არჩევით). სიიდან სტრიქონზე დაჭერა ახლა დეტალს ხსნის.
> **ხარჯის ჩანაწერის რედაქტირება და წაშლა** შესრულებულია (2026-10-27): ადმინს ყველა სტატუსში, როგორც საიტზე; რედაქტირებისას ახალი სურათები არსებულს ემატება, Telegram არჩევით; წაშლა დადასტურებით და Telegram-ით ყოველთვის. იგივე წესებით **ჩარიცხვის რედაქტირება და წაშლა** (რედაქტირებისას კლიენტის ელ-ფოსტაც არჩევით).
> **პროექტის დამატება/რედაქტირება** შესრულებულია (2026-10-27): `POST /admin/expenses`, `PUT /admin/expenses/:id` (ადმინს, Telegram არჩევით); აპში „+" სიაში და „რედაქტირება" დეტალზე. დამკვეთის და საჯარო პროექტის ID ტექსტურად შეიყვანება, როგორც საიტზე.
> დარჩენილი: დოკუმენტები, ხარჯის ტიპების მართვა, ხარჯის `userId` ველი.

## რა არის საიტზე

**წვდომა:** `routes/admin/expenses.route.js` → `router.use(isAdminMiddleware)`. გვერდზე შედის ადმინიც და მოდერატორიც; მოდერატორს მხოლოდ ნახვა შეუძლია (`isReadOnlyModerator`), წაშლის ღილაკი მხოლოდ ადმინს უჩანს.

**სია (`GET /admin/expenses-list`):**
- ფილტრი სტატუსით: „ყველა“ + `დასაწყები 🚀`, `მიმდინარე 🔄`, `დასრულებული ✅`, `შეწყვეტილი ⛔` (`?status=`).
- 20 ჩანაწერი გვერდზე, უახლესი პირველი (`createdAt` ↓), გვერდებად.
- ბარათზე: რიგითი ნომერი, პროექტის სახელი, სტატუსის ბეჯი, ჯამური ღირებულება, ჯამური ხარჯი (წითლად), დარჩენილი თანხა (მწვანედ), მიმდინარე თანხა (`totalAmount − remainingAmount − totalExpenses`, ფერი ნიშნის მიხედვით), პროექტის პროგრესი (`getProjectProgress(startDate, endDate)` — დროზე დაფუძნებული %), ღილაკები „ნახვა“ და (ადმინს) „წაშლა“ დადასტურებით.
- წაშლა: `POST /admin/expenses/delete/:id` → ჩანაწერის წაშლა + Telegram შეტყობინება „პროექტი წაიშალა“.

**დანარჩენი ხარჯების მოდული (ამ ეტაპის მიღმა):** პროექტის დამატება/რედაქტირება; დეტალური გვერდი (6 მაჩვენებელი, პროგრესი, ხარჯები ტიპების მიხედვით, დოკუმენტები, ჩარიცხვები, ხარჯის ჩანაწერები სურათებით); ჩარიცხვის დამატებისას კლიენტს ეგზავნება ელ-ფოსტა; ხარჯის ტიპების CRUD; თითქმის ყველა ცვლილება Telegram-ში იგზავნება.

**API:** დღეს ხარჯების endpoint-ები არ არსებობს. `apiAuth` ამოწმებს მხოლოდ Bearer ტოკენს; როლების შემოწმება API-ში ჯერ არ არის.

## ეტაპი 1 — სია

### Backend (renovatori)

1. **`middleware/api-staff.middleware.js`** — `apiAuth`-ის შემდეგ მომხმარებელს **ბაზიდან** კითხულობს (ტოკენის როლები 1 საათამდე შეიძლება მოძველდეს) და უშვებს მხოლოდ `isAdmin || isModerator`-ს; სხვას — `403 forbidden`. ცალკე `requireAdmin` ჩასაწერი ოპერაციებისთვის (მოდერატორი → `403 forbidden`).
2. **`routes/api/v1/admin/expenses.route.js`** (`/api/v1/admin/expenses`):
   - `GET /` — `?status=&page=&pageSize=` (default 20, max 50) → `{ data: ExpenseCard[], pagination }`. არასწორი სტატუსი = ფილტრის გარეშე, როგორც საიტზე.
   - `GET /statuses` — `{ data: { statuses: [...] } }` (ფილტრის ჩიპებისთვის, რომ სტატუსები აპში არ დავაკოდოთ).
   - `DELETE /:id` — მხოლოდ ადმინი; 404 `not_found` არასწორ/უცნობ id-ზე; იგივე Telegram შეტყობინება, რაც საიტზე → `{ data: { deleted: true } }`.
3. **`serializeExpenseCard`** (`helpers/api-serializers.js`): `id, projectName, projectStatus, totalAmount, totalExpenses, remainingAmount, currentAmount` (სერვერზე გამოთვლილი), `startDate, endDate, progress: { percent, label, isValid }` (`getProjectProgress`-იდან), `createdAt`.
4. რეგისტრაცია `routes/api/v1/index.js`-ში და `docs/agents/swift-rules/README.md`-ის განახლება.
5. AGENTS.md: JSDoc ყველა ფუნქციაზე, კომენტარი ყველა `if`-ზე; ადმინ API მარშრუტები `admin`-ის ქვეშ.

### აპი (renovatori-app-swift)

1. **მოდელები** — `Content/ExpenseModels.swift`: `ExpenseCard`, `ExpenseProgress`, `ExpenseStatus` (უცნობი სტატუსიც უნდა დაიშიფროს, ძველი `დაწყებული` → `დასაწყები`, როგორც საიტზე).
2. **ნავიგაცია** — `AppRoute.expenses`. ☰ მენიუში ცალკე „ადმინისტრირება“ ნაწილი „ხარჯები“ პუნქტით, რომელიც ჩანს **მხოლოდ** `isAdmin || isModerator`-ზე; იგივე ბმული პროფილშიც.
3. **`Views/Admin/ExpensesListView.swift`**:
   - ზემოთ ფილტრის ჩიპები (ჰორიზონტალური `ScrollView`, „ყველა“ + სტატუსები ემოჯით).
   - `List` + არსებული `PagedList` (ავტომატური ჩატვირთვა ბოლოში, `refreshable`).
   - სტრიქონი: სახელი + სტატუსის ბეჯი (ფერები: მიმდინარე — ცისფერი, დასრულებული — მწვანე, შეწყვეტილი — წითელი, დასაწყები — ლურჯი), 4 თანხა 2×2 ბადეში, `ProgressView` წარწერით.
   - თავში „სულ ჩანაწერები: N“.
   - ადმინს — swipe „წაშლა“ `confirmationDialog`-ით (AGENTS.md: წაშლა ყოველთვის დადასტურებით); მოდერატორს წაშლა არ უჩანს.
   - ცარიელი სია → `ContentUnavailableView` „ჩანაწერები არ მოიძებნა.“; `403` → „წვდომა არ გაქვთ“.
   - სტრიქონზე დაჭერა ეტაპ 1-ში არაფერს ხსნის (ან საიტის დეტალურ გვერდს — იხ. ღია კითხვები).

### შემოწმება

- API (დროებით სერვერზე Telegram-ის გარეშე): სტუმარი → 401, ჩვეულებრივი მომხმარებელი → 403, მოდერატორი → სია ✓ / წაშლა 403, ადმინი → სია/ფილტრი/გვერდები/წაშლა ✓, არასწორი id → 404.
- აპი სიმულატორში ადმინის და მოდერატორის ანგარიშით: მენიუს პუნქტის ხილვადობა, ფილტრი, ბოლომდე ჩამოსქროლვა, წაშლის დადასტურება.
- ლოკალურ ბაზაში საჭიროა ტესტური ადმინი და მოდერატორი (არსებულ ტესტ ანგარიშს `isAdmin`/`isModerator` დაუყენდება მხოლოდ ლოკალურ ბაზაში).
